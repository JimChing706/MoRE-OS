**评估日期**: 2026-10-04
**评估对象**: "产出正确性 / 交付可信度 / 可观测性"三大硬伤的全链路整改成果
**评估方式**: 需求逐条对照 + 源码走读 + 全量回归 + **真实浏览器/真实模型端到端取证**

## 1. 需求 1 — 结构化根因分析

**交付物**：`docs/RCA_AND_FIX_2026-10-04.md`

| 硬伤 | 触发节点 | 影响范围 | 底层成因 |
|------|----------|----------|----------|
| 产出正确性 | `orchestrator.py` 交付前脱敏 | MoRE 自身源码 **135 行 / 49 文件**会被改写 | `env_secret` 正则匹配 Python 关键字参数（`key=lambda` → `[ENV_SECRET_REDACTED]`）；且**验证对象 ≠ 交付对象**，无闸门拦截 |
| 交付可信度 | `execute()` 返回前 | 全部交付物 | 无台账/版本/权责/哈希，成功率无模型；坏结果还会进缓存扩散 |
| 可观测性 | `LLMManager` 各入口 + 遥测单例 | 全部 LLM 调用 | ① 存储模块导入路径错误；② **4 个入口只插桩 1 个**（L0 实走 `generate_with_fallback_chain`） |

**评级 A**：三项均给出触发节点、影响范围与底层成因，且每条都附可复现的失败样例。

## 2. 需求 2a — 产出正确性

### 2.1 交付的能力

| 能力 | 实现 | 拦截强度 |
|------|------|:--------:|
| **语法检查** | Python `compile()` 真实解析；Rust/TS 等括号/引号配平 | **blocking** |
| **逻辑验证** | 空函数体 / `pass` 占位 / `NotImplementedError` / `TODO` / `placeholder` 检测 | **blocking**（短产物） |
| **需求匹配度** | 从标题/描述/验收标准抽取关键点，计算覆盖率（阈值 40%） | **blocking** |
| **错误拦截** | 闸门未过 → 任务降级 `FAILED` + `delivery_blocked` 审计 + **不入缓存** | — |
| **交付一致性** | 过滤前后语法对比，若过滤破坏代码则回退到过滤前工件并记审计 | — |

### 2.2 实测取证（真实任务）

```
闸门结论: True
  - syntax       ok=True  1 个代码块语法通过
  - logic        ok=True  25 行代码
  - requirement  ok=True  需求符号覆盖 1/1 = 100%
交付代码编译: PASS
含占位符    : False
key=lambda  : True     ← 证明 F-01 的代码破坏已修复
```

**评级 A-**：拦截机制真实生效、有 25 项单测覆盖；但"逻辑验证"目前是**静态启发式**，
只能识别占位/空实现，无法发现"看起来完整但逻辑错误"的代码（需靠断言路径兜底）。

## 3. 需求 2b — 交付可信度

### 3.1 交付的能力

## 4. 需求 2c — 可观测性

### 4.1 交付的能力

| 要求 | 实现 |
|------|------|
| **token 消耗采集** | `llm_calls` 表记录 prompt/completion tokens；**4 个 LLM 入口全部插桩**（`generate` / `generate_with_fallback_chain` / `generate_parallel` / `stream`） |
| **请求延迟采集** | 每次调用记录 `latency_ms`；聚合 avg/p50/p95/max |
| 存储 | SQLite（WAL），索引 `(ts)` / `(provider,model)` / `(success)` |
| 实时查询 | `/api/v1/metrics/llm`（聚合）、`/metrics/llm/recent`（明细）、`/health` 内嵌 `tokens_1h` / `latency_ms_1h` |
| **可视化** | ① API 自托管看板 `/api/v1/metrics/dashboard`；② **前端 Home 概览页遥测面板**（1h/6h/24h 窗口，5s 自动刷新） |
| 覆盖率 | LLM 调用 + 交付台账；区分 `measured_calls` / `cached_calls` / `failed_calls` |

## 6. 评估过程中发现并当场闭环的新问题

| ID | 问题 | 证据 | 处置 |
|----|------|------|------|
| **G1** | 台账 `status=delivered` 与控制器 `verdict=escalated` **自相矛盾** | 首个评估任务实测即出现 | ✅ 新增 `codegen/delivery_policy.py` 做交叉校验：escalated → `blocked`；并**限定只对代码类任务生效**（避免误伤 NLP 任务） |
| **G2** | 失败/缓存调用以 `latency=0` 落库，**把 p50 拉到 0** | `samples=12, cached=0, p50=0.0` | ✅ 分位只统计"成功且非缓存"；新增 `measured_calls` / `failed_calls` |
| **R-20** | escalated 只记"沙箱失败 3/3 轮"，**不保留真实失败原因**，真假阴性无法区分 | `verdict.artifacts` 无 error 字段 | ✅ 新增 `last_error` / `last_output_tail` / `timed_out` |
| — | 测试夹具未注册 `python_exec`，导致代码任务永远不进沙箱 | `core.tools.get("python_exec") is None` | ✅ conftest 注册 builtins，对齐生产 bootstrap |

新增回归测试：`test_delivery_policy_and_metrics.py`（10 项）+ 相关测试契约更新。
